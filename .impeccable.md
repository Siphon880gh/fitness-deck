## Design Context

### Users
- **In-session trainer** — Mid-workout on phone/tablet; needs the right progression table fast, marks the variation in use, and optionally runs timer or reps without leaving the page.
- **Progression learner** — Reviews the catalog to learn variations; marks addressed cells, reads notes, filters by color, leaves comments.
- **Goal-seeking starter** — First visit or problem-led (“stretch hips”, “build with minimal gear”, “shin rehab”); picks a program by goal and reaches a useful table in few taps.

Returners resume via last-opened; newcomers orient via goal-first directory. Progress stays on-device (no accounts).

### Brand Personality
Utilitarian, athletic, calm. A sharp personal training reference—not a fitness SaaS pitch. Voice is direct and spare: name the job, get out of the way.

### Aesthetic Direction
- Light graphite base with one deep olive/teal athletic accent; high contrast for gym lighting.
- Display + body pairing with character (not Inter/system defaults).
- Motion: entry reveal, continue focus, notes panel — transform/opacity only; honor `prefers-reduced-motion`.
- Anti-references: purple gradients, cream+terracotta editorial, dark neon glow, dashboard hero clutter, unlabeled FAB mystery rows.

### Design Principles
1. **Job first** — Entry and chrome answer “what am I here to do?” before listing every file.
2. **Resume in one tap** — Last session is a primary action, not a hidden toggle.
3. **Teach once** — Color meaning and tools appear once, then stay labeled and quiet.
4. **One product** — Directory and table share tokens, type, and accent so the tool feels continuous.
5. **Preserve the core** — Markdown decks, DataTables marking, IndexedDB — redesign presentation, not the data model.
